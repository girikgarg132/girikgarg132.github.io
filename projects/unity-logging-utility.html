The Problem: Default Debug.Log in Production

In production Unity projects, standard Debug.Log calls present three critical drawbacks that harm both development velocity and shipping performance:

  • Unformatted Console Noise: As projects expand across networking, audio, AI, UI, and physics, the console quickly becomes a wall of white text. Crucial warnings and runtime exceptions are buried under routine status messages.
  • Garbage Collection & Memory Allocation: String concatenations and string interpolations (e.g. $"Player position: {pos}") allocate heap memory every execution. In high-frequency game loops, this causes constant GC allocations and frame stutter.
  • Severe Release Build Penalties: Unlike some compiled languages, Unity's default Debug.Log statements execute in production builds unless explicitly wrapped in preprocessor defines. This wastes CPU cycles on mobile devices and leaks proprietary game logic, packet structures, or API payloads into logcat and crash reports.

Architectural Capabilities & Features

UnityLoggingUtility was built to provide high-clarity console visibility during development while guaranteeing zero performance impact in release builds:

Color-Coded Categories

Assign custom hex colors and bracket tags to categories (e.g., [Network], [Combat], [UI]) for instant visual scanning in the console.

Live Category Toggles

Toggle individual log categories on or off on the fly during play mode to silence noisy subsystems while debugging specific features.

Compile-Time Stripping

Decorated with C# [Conditional] attributes. In release builds, the compiler completely strips log calls and string arguments with 0 GC and 0 CPU overhead.

Automated CodeGen

Configure categories, colors, and stripping rules in a centralized settings window to automatically generate GGLog and GGLogCategory helper scripts.

Implementation & Code Architecture

The utility auto-generates dedicated, strongly-typed static logging methods decorated with conditional attributes tied to compiler symbols:

Generated Logging Architecture (GGLog.cs) 
// Auto-generated helper with compile-time stripping
[System.Diagnostics.Conditional("ENABLE_LOG_NETWORK")]
public static void LogNetwork(string message, UnityEngine.Object context = null)
{
    if (!IsCategoryEnabled(GGLogCategory.Network)) return;
    
    // Rich-text color formatting applied automatically
    UnityEngine.Debug.Log($"<color=#38bdf8>[Network]</color> {message}", context);
}

[System.Diagnostics.Conditional("ENABLE_LOG_COMBAT")]
public static void LogCombat(string message, UnityEngine.Object context = null)
{
    if (!IsCategoryEnabled(GGLogCategory.Combat)) return;
    UnityEngine.Debug.Log($"<color=#fb7185>[Combat]</color> {message}", context);
}
Clean Gameplay Calling Code 
// In your gameplay and network scripts:
GGLog.LogNetwork($"Host listening on port {listenPort} (Relay Connected)");
GGLog.LogCombat($"Player {playerID} dealt {damage} elemental damage to {target.name}");

// In release builds:
// The compiler completely removes both the method call AND string allocations!

Installation via Unity Package Manager (UPM)

Add this package directly into your project using the Unity Package Manager Git dependency:

Unity Package Manager — Git URL 
https://github.com/girikgarg132/UnityLoggingUtility.git#v1.0.0

Setup & Workflow:

  • Open the centralized settings window in Unity.
  • Add your project categories (e.g., UI, Audio, Combat, Network, AI) and assign colors.
  • Configure your build-stripping rules per build target and scripting define symbols.
  • Click Generate to create your strongly-typed GGLog utility.
