The Vision & Core Loop

Elebend was conceptualized to solve a major issue in traditional mobile and PC real-time strategy games: balancing high-ceiling APM (actions per minute) mechanics with accessible touch and mouse-driven controls.

Players command primordial elemental deities embodying Fire, Water, Earth, Wind, Thunder, and Gravity. Combat takes place across dynamic elemental conduits where units must be deployed to capture mana streams, react to terrain hazards, and time synergistic skill triggers against opponent counters.

Technical Architecture & Engineering

My work on Elebend centered around core gameplay architecture, cross-platform input abstraction, and real-time state synchronization:

  • Cross-Platform Input Abstraction: Unified input pipeline in Unity handling dual touch-gestures, drag-and-drop targeting on mobile, alongside precise click-and-drag box selection and keyboard shortcuts on Steam PC.
  • Real-Time Mana Flow & Conduit Mechanics: Engineered a custom grid-and-node flow calculation system representing elemental currents, optimized to update seamlessly without GC (garbage collection) frame spikes.
  • Deterministic Unit State Machines: Built modular state machines for diverse unit archetypes (melee vanguard, elemental casters, siege guardians) using decoupled ScriptableObject event architectures.
  • Performance Profiling on Mobile: Optimized draw calls through sprite atlasing, dynamic batching, and custom shader LODs to maintain a steady 60 FPS on mid-range Android devices.

Key Challenges & Solutions

Challenge: Maintaining High Responsiveness Over Variable Latency.
In competitive RTS matches, players expect immediate feedback when issuing move or spell commands. By implementing client-side prediction for unit path previews combined with authoritative server state reconciliation, we ensured that players never felt sluggish delay even under unsteady network jitter.

Challenge: Asset & Memory Management for Live-Service.
With ongoing updates of seasonal skins, new elemental abilities, and arenas, memory bloat was an initial risk. We structured the game around Addressables, lazy-loading audio assets and character VFX bundles strictly when required in the match scene.
